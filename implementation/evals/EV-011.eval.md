# Eval — EV-011

```
Tipo   : trayectoria
Origen : hallazgo del crítico, pasada 5 (9 sep 2026)
Cubre  : la CSP y images.remotePatterns solo aceptan hosts concretos, nunca comodines
Creado : 2026-09-09
```

---

## Comando

```bash
node implementation/evals/checks/csp-sin-comodines.mjs
```

## Caso

**Entrada**
`next.config.mjs`: las directivas de `Content-Security-Policy` y los `hostname` de
`images.remotePatterns`.

**Salida esperada**
```
CSP y remotePatterns sin comodines: todos los orígenes son hosts concretos.
```
Exit 0.

**Qué NO debe pasar**
- Una directiva con el esquema suelto (`https:`, `http:`): acepta **cualquier** host.
- Un `*` o un `*.dominio` en una directiva o en un `hostname`.
- Un `hostname: "**"` en `remotePatterns`: convierte `/_next/image` en un proxy abierto (SSRF).

**Lo que NO cuenta como comodín**: `'self'`, `'none'`, `data:` y `blob:` acotan a origen
propio o a datos embebidos; no abren la puerta a un tercero.

---

## Por qué existe

`img-src 'self' https: data:` estaba en el proyecto desde el principio. `remotePatterns`
sí respetaba la regla —solo `i.ytimg.com` e `img.youtube.com`, y con un comentario
explicando el riesgo de SSRF— pero la CSP aceptaba cualquier host HTTPS.

Nadie lo había mirado en cinco días de revisión porque la constitución nombraba
`remotePatterns` de forma explícita y la CSP solo de pasada. **Lo que se nombra se revisa;
lo que se da por supuesto, no.**

El crítico además comprobó que el comodín no protegía nada real: `grep` de los `src`/`href`
del HTML generado no devuelve **ningún** host externo de imagen hoy, porque `youtubeIds`
está vacío.

## Trayectoria

- [x] **Rojo primero**: con `img-src 'self' https: data:` intacto, exit 1 nombrando la
      directiva y el valor
- [x] Verde tras acotar a los dos hosts que ya estaban en `remotePatterns`
- [x] No salta con `'self'`, `'none'` ni `data:`
