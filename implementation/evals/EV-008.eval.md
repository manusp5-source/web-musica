# Eval — EV-008

```
Tipo   : trayectoria
Origen : hallazgo de la review del 5-6 sep 2026 (revisor, bloqueante 3)
Cubre  : en la ruta de render no existe ningún filtro por puntuación
Creado : 2026-09-06
```

---

## Comando

```bash
node implementation/evals/checks/sin-filtro-por-rating.mjs
```

## Caso

**Precondición**
Ninguna. Es análisis de la ruta de render: `Reviews.tsx`, `load.ts` y `jsonld.ts`.

**Entrada**
El código de esos tres ficheros, sin comentarios (un `// nunca filtres por rating < 4` no
es un filtro).

**Salida esperada**
```
Sin filtros por puntuación en 3 ficheros de la ruta de render.
```
Exit 0.

**Qué NO debe pasar**
- Una comparación numérica sobre `rating` / `ratingValue` (`>= 4`, `> 3`, `< 5`).
- Un `.filter()` que mencione `rating`.
- Que uno de los tres ficheros desaparezca sin que nadie actualice este eval: se trata como
  fallo, no como «no aplica». Si la lógica se mudó, este eval dejó de vigilar la ruta real.

**Falsos positivos que NO debe dar**
`Math.round(file.aggregate.rating)` y `ratingValue: r.rating` son uso legítimo. Por eso se
busca el **operador de comparación**, no la palabra `rating`.

---

## Por qué existe

El principio 4 de `design/constitution.md` dice que las reseñas se publican sin filtrar, y
el motivo no es estético: el RDL 24/2021 (Directiva Omnibus, Anexo I) tipifica como
práctica desleal mostrar solo las positivas ocultando las negativas.

Hasta esta review **nadie lo vigilaba**. El `README.md` de evals listaba `EV-008` como
pendiente, pero el fichero no existía, y `run.mjs` recorre el directorio: no puede echar en
falta un eval que no está. Un eval listado y ausente es peor que uno que falta, porque
parece cubierto.

## La v1 tenía un agujero y se lo encontró el crítico

**Es el quinto falso verde del proyecto, y estaba dentro del eval escrito para evitarlo.**

La v1 llevaba la ruta de render **escrita a mano**: `Reviews.tsx`, `load.ts`, `jsonld.ts`.
El crítico de `/review` plantó esto en `HomePage.tsx`, que no estaba en la lista:

```ts
const cargado = loadReviews();
const reviews = { ...cargado, reviews: cargado.reviews.filter((r) => r.rating >= 4) };
```

Con ese filtro ilegal vivo, **la suite entera siguió verde**: `npm run lint` sin avisos,
37/37 unitarios, 7 evals PASA incluido este. Un eval que enumera lo que vigila solo
protege de lo que ya se te había ocurrido.

**La v2 no añade `HomePage.tsx` a la lista: descubre la ruta de render.** Recorre `src/` y
`app/` y vigila todo fichero que mencione `lib/reviews`, `loadReviews`, `visibleReviews` o
`buildRatingJsonLd`, más un núcleo fijo de tres. Un consumidor nuevo entra solo.
