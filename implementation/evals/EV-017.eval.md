# Eval — EV-017

```
Tipo   : trayectoria
Origen : hallazgo del crítico en la review (11 sep 2026)
Cubre  : ninguna sección con id queda sin un enlace entrante en toda la página
Creado : 2026-09-11
```

---

## Comando

```bash
npx vitest run tests/unit/anclas-vivas.test.tsx
```

## Caso

**Entrada**: `HomePage` renderizado completo, en los dos locales.

**Salida esperada**: 3 tests en verde.

- Todo `<section id="...">` tiene al menos un `href="#ese-id"` en algún sitio de la
  página renderizada, en ES y en EN.
- El CTA principal del hero (`dict.hero.ctaPrimary`, «Ver tarifa y reservar») enlaza de
  verdad a `#tarifa`.

**Qué NO debe pasar**
- Una sección nueva sin ningún enlace que lleve a ella.
- Que se cuenten como «ancla de navegación» los `id` de los campos de un formulario
  (`cf-name`, `cf-email`...), que existen para su `<label htmlFor>`, no para un `href`.

---

## Por qué existe

El crítico encontró que `#tarifa` —la sección con el precio publicado, una de las tres
patas del posicionamiento del plan de negocio (§4)— **no tenía ningún enlace entrante en
toda la página**. El CTA principal decía «Ver tarifa y reservar» y llevaba a `#contacto`;
`Nav.tsx` no la listaba entre sus enlaces. Confirmado contra el HTML real:
```
anclas: #top #servicios #media #sobre-mi #eventos #contacto
ids:    top servicios tarifa media sobre-mi eventos contacto
```
`tarifa` sobraba en la segunda lista y faltaba en la primera.

Generalizado en vez de fijado a un solo caso: si mañana aparece otra sección sin
enlazar, este eval se pone rojo solo — mismo principio de descubrimiento que ya usan
`EV-008`, `EV-013` y `EV-015`.

## Falso positivo propio en la primera pasada

La primera versión buscaba cualquier `id="..."` en el HTML, y contó los `id` de los
campos del formulario de contacto (`cf-name`, `cf-email`, `cf-phone`...) como anclas de
navegación sin enlace — que es justo para lo que **no** sirven esos `id`: están ahí para
que `<label htmlFor="cf-name">` los referencie, no para recibir un `href="#cf-name"`.
Corregido acotando la búsqueda a `<section id="...">`, que es donde viven las anclas
reales de este proyecto.
